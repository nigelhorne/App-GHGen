 1165: =head1 LIMITATIONS
 1166: 
 1167: =over 4
 1168: 
 1169: =item * Workflows are text templates, not data
 1170: 
 1171: Every generator except C<perl> is a heredoc, and C<--versions> works by
 1172: regex-rewriting that text.  It is tied to the exact layout of each template
 1173: (indentation, the C<ubuntu-latest> job line, the pinned Go and Rust lines)
 1174: and a template edit can silently stop it matching.  Building each workflow as
 1175: a Perl data structure and serialising it with L<YAML::XS> would remove the
 1176: whole class of problem; that is a rewrite of every generator, so it is not
 1177: done here.  The tests in F<t/versions_option.t> parse the output as YAML to
 1178: catch a broken rewrite.
 1179: 
 1180: =item * Default versions are fixed in the templates
 1181: 
 1182: The defaults are not validated against what the setup actions support today,
 1183: and some are end of life (node 18, python 3.9, ruby 3.1).  They are kept so
 1184: existing output does not change.
 1185: 
 1186: =item * One version list per run
 1187: 
 1188: C<--versions> applies to the single generated type.  There is no way to give
 1189: different lists to different jobs in one workflow.
 1190: 
 1191: =item * Messages are sprintf formats only
 1192: 
 1193: C<%MESSAGES> can be reworded or translated by replacing its values, but there
 1194: is no plural or grammatical-gender handling, and the table is a package
 1195: global rather than per-object configuration.  The messages here take only
 1196: strings, so none is needed yet.
 1197: 
 1198: =item * Version tokens are checked for safety, not meaning
 1199: 
 1200: C<9.9.9> is accepted for any language.  Whether the setup action can install
 1201: it is only discovered when the workflow runs.
 1202: 
 1203: =item * Perl ignores project detection when versions are given
 1204: 
 1205: C<generate_workflow('perl', { versions => ... })> uses exactly the list given;
 1206: the minimum Perl detected from F<cpanfile> or F<Makefile.PL> is not applied.
 1207: 
 1208: =back
