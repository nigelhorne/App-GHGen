 1163: =head1 LIMITATIONS
 1164: 
 1165: =over 4
 1166: 
 1167: =item * Workflows are text templates, not data
 1168: 
 1169: Every generator except C<perl> is a heredoc, and C<--versions> works by
 1170: regex-rewriting that text.  It is tied to the exact layout of each template
 1171: (indentation, the C<ubuntu-latest> job line, the pinned Go and Rust lines)
 1172: and a template edit can silently stop it matching.  Building each workflow as
 1173: a Perl data structure and serialising it with L<YAML::XS> would remove the
 1174: whole class of problem; that is a rewrite of every generator, so it is not
 1175: done here.  The tests in F<t/versions_option.t> parse the output as YAML to
 1176: catch a broken rewrite.
 1177: 
 1178: =item * Default versions are fixed in the templates
 1179: 
 1180: The defaults are not validated against what the setup actions support today,
 1181: and some are end of life (node 18, python 3.9, ruby 3.1).  They are kept so
 1182: existing output does not change.
 1183: 
 1184: =item * One version list per run
 1185: 
 1186: C<--versions> applies to the single generated type.  There is no way to give
 1187: different lists to different jobs in one workflow.
 1188: 
 1189: =item * Messages are sprintf formats only
 1190: 
 1191: C<%MESSAGES> can be reworded or translated by replacing its values, but there
 1192: is no plural or grammatical-gender handling, and the table is a package
 1193: global rather than per-object configuration.  The messages here take only
 1194: strings, so none is needed yet.
 1195: 
 1196: =item * Version tokens are checked for safety, not meaning
 1197: 
 1198: C<9.9.9> is accepted for any language.  Whether the setup action can install
 1199: it is only discovered when the workflow runs.
 1200: 
 1201: =item * Perl ignores project detection when versions are given
 1202: 
 1203: C<generate_workflow('perl', { versions => ... })> uses exactly the list given;
 1204: the minimum Perl detected from F<cpanfile> or F<Makefile.PL> is not applied.
 1205: 
 1206: =back
