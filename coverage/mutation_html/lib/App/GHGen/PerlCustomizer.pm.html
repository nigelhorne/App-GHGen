  197: 
  198: =item C<enable_linter> (boolean, default C<1>)
  199: 
  200: When true, inserts a B<"Lint and syntax check"> step after all dependency
  201: installation steps and before the test run.  The step runs on B<every>
  202: matrix cell (all OS and Perl version combinations) so that compile-time
  203: errors are caught across the full version range being tested.
  204: 
  205: The step uses C<shell: perl {0}>, which works identically on Linux, macOS,
  206: and Windows without any OS-specific branching.  It searches C<lib/> and
  207: C<bin/> (falling back to C<.> when neither exists), loads each C<.pm> file

  210: C<do $file> avoids spawning C<perl -c> subprocesses (which have
  211: Windows command-line quoting issues) and avoids false failures caused by
  212: missing CPAN dependencies.  B<No additional CPAN modules are required.>
  213:

  215:

  224: 
  225: =item C<enable_critic> (boolean, default C<1>)

  229: 
  230: =item C<enable_coverage> (boolean, default C<1>)

  625: =head1 LIMITATIONS
  626: 
  627: =head2 Windows + Perl 5.40 excluded from the generated matrix
  628: 
  629: The shogo82148 C<perl-5.40.4-thr-win32-x64.zip> distribution ships a
  630: C<perl.exe> and a C<libperl540.a> from two different builds.  Any XS module
  631: compiled against that C<libperl540.a> receives handshake key
  632: C<0x12c00080>, but C<perl.exe> needs C<0x12d00080>.  Even
  633: C<Win32::Process> - a core Windows XS module bundled in the zip and loaded
  634: transitively by C<IPC::System::Simple> - fails to load with this mismatch,
  635: so no XS-using test can pass on this combination.
  636: 
  637: Recompiling XS modules (e.g. via C<cpanm --reinstall YAML::XS>) does not
  638: help: the compilation itself links against the broken C<libperl540.a> and
  639: inherits the wrong key.
  640: 
  641: The generated workflow therefore includes a C<matrix.exclude> entry for
  642: C<{os: windows-latest, perl: '5.40'}>.  This entry is only emitted when
  643: both C<windows-latest> and C<5.40> are present in the matrix, so workflows
  644: that restrict their OS or Perl lists are unaffected.
  645: 
  646: Remove the exclusion once the upstream shogo82148/build-perl distribution
  647: is fixed and the C<perl.exe> and C<libperl540.a> in the 5.40.x zip are
  648: built from the same source tree.
  649: 
  650: See L<https://github.com/shogo82148/actions-setup-perl/issues/2310> for further information.
