  184: 
  185: =item C<enable_linter> (boolean, default C<1>)
  186: 
  187: When true, inserts a B<"Lint and syntax check"> step after all dependency
  188: installation steps and before the test run.  The step runs on B<every>
  189: matrix cell (all OS and Perl version combinations) so that compile-time
  190: errors are caught across the full version range being tested.
  191: 
  192: The step uses C<shell: perl {0}>, which works identically on Linux, macOS,
  193: and Windows without any OS-specific branching.  It searches C<lib/> and
  194: C<bin/> (falling back to C<.> when neither exists), loads each C<.pm> file
  195: via C<do $file> with a stub C<@INC> handler that silently satisfies any
  196: missing C<use> statements, and exits non-zero if any file fails.  Using
  197: C<do $file> avoids spawning C<perl -c> subprocesses (which have
  198: Windows command-line quoting issues) and avoids false failures caused by
  199: missing CPAN dependencies.  B<No additional CPAN modules are required.>
  200: 
  201: =item C<enable_linter_unused> (boolean, default C<1>)
  202: 
  203: When true, appends an unused-variable check to the B<end of the lint step>

  207: exercised at runtime (C<perl -c> is compile-only and cannot detect unused
  208: variables).  It is gated on C<RUNNER_OS == Linux> and marked

  210: legitimately noisy on some codebases.
  211: 
  212: =item C<enable_critic> (boolean, default C<1>)
  213:

  216:

  602: =head1 LIMITATIONS
  603: 
  604: =head2 Windows + Perl 5.40 excluded from the generated matrix
  605: 
  606: The shogo82148 C<perl-5.40.4-thr-win32-x64.zip> distribution ships a
  607: C<perl.exe> and a C<libperl540.a> from two different builds.  Any XS module
  608: compiled against that C<libperl540.a> receives handshake key
  609: C<0x12c00080>, but C<perl.exe> needs C<0x12d00080>.  Even
  610: C<Win32::Process> â€” a core Windows XS module bundled in the zip and loaded
  611: transitively by C<IPC::System::Simple> â€” fails to load with this mismatch,
  612: so no XS-using test can pass on this combination.
  613: 
  614: Recompiling XS modules (e.g. via C<cpanm --reinstall YAML::XS>) does not
  615: help: the compilation itself links against the broken C<libperl540.a> and
  616: inherits the wrong key.
  617: 
  618: The generated workflow therefore includes a C<matrix.exclude> entry for
  619: C<{os: windows-latest, perl: '5.40'}>.  This entry is only emitted when
  620: both C<windows-latest> and C<5.40> are present in the matrix, so workflows
  621: that restrict their OS or Perl lists are unaffected.
  622: 
  623: Remove the exclusion once the upstream shogo82148/build-perl distribution
  624: is fixed and the C<perl.exe> and C<libperl540.a> in the 5.40.x zip are
  625: built from the same source tree.
  626: 
  627: See L<https://github.com/shogo82148/actions-setup-perl/issues/2310> for further information.
